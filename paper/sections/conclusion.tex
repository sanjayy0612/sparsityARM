\section{Conclusion}

We asked whether contiguous FFN blocks can turn dynamic sparsity into
practical CPU speedups on an Apple M2 without unacceptable quality loss.
Llama 3.2 1B and TinyLlama 1.1B tolerate only 10--20\% B8 block sparsity under
a 5\% perplexity gate. A packed block executor needs 40--50\% sparsity to beat
dense, so it never reaches a useful operating point, but a per-neuron executor
with neuron-major weights runs the same block-aligned masks faster than dense
at the quality ceiling, by a few percent. On this hardware, block alignment
helps through memory layout rather than packed kernels, and the quality
ceiling caps the possible FFN gain at 11--25\%. The main obstacle to larger
gains is block-compatible model representation. We release the complete
evidence as a baseline for methods that train block-compatible structure.
